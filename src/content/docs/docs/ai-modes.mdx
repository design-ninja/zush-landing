## Compare AI modes

| Mode | Where analysis runs | Best for |
| --- | --- | --- |
| [Zush Cloud AI](/docs/zush-cloud-ai) | Managed cloud analysis | The fastest setup: no API key or local model required |
| [BYOK](/docs/byok) | Your selected cloud provider | Using your own Gemini, OpenRouter, OpenAI, or Claude API key |
| [Ollama](/docs/offline-ai) | Your local Ollama server | Setting up a suggested local model with Zush, or using models you already manage |
| [LM Studio](/docs/lm-studio) | Your local LM Studio server | Choosing and tuning vision-capable local models in LM Studio |

## How to choose

- Choose **Zush Cloud AI** when you want to start immediately.
- Choose **BYOK** when you want a specific cloud provider account, model, or billing path.
- Choose **Ollama** when you want guided local setup in Zush or already use Ollama.
- Choose **LM Studio** when you already use its model catalog and local server controls.

Only one AI mode is active at a time. When Ollama or LM Studio is selected, Zush does not silently fall back to cloud analysis.

The selected mode applies across AI Rename, Quick Rename, and Monitor. Templates save naming and sorting settings, not an independent AI provider or model connection.

## Quality and performance

Cloud models are usually the simplest option for complex mixed folders. Local quality and speed depend on the model, file type, available memory, and computer hardware. Test a representative small batch before assigning any mode to folder monitoring.

For media, check [Audio and video analysis](/docs/audio-video): local models use available text, metadata, and visual previews rather than receiving raw audio for cloud-style transcription.
