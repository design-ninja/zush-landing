## Compare AI modes

| Mode | Where analysis runs | Best for |
| --- | --- | --- |
| [Zush Cloud AI](/docs/zush-cloud-ai) | Zush-managed cloud analysis | The fastest setup: no API key or local model required |
| [Local AI](/docs/local-ai) | Built into Zush on your Mac | Private offline analysis with a model downloaded and managed by Zush |
| [LM Studio](/docs/lm-studio) | Your local LM Studio server | Choosing and tuning vision-capable local models in LM Studio |
| [BYOK](/docs/byok) | Your selected cloud provider | Using your own Gemini, Groq, OpenAI, or Claude API key |
| [Ollama](/docs/offline-ai) | Your local Ollama server | Running models you already manage with Ollama |

## How to choose

- Choose **Zush Cloud AI** when you want to start immediately.
- Choose **Local AI** when supported analysis must stay on your Mac and you want Zush to manage the local runtime and model.
- Choose **LM Studio** when you already use its model catalog and local server controls.
- Choose **BYOK** when you want a specific cloud provider account, model, or billing path.
- Choose **Ollama** when you already manage local models through Ollama.

Only one AI mode is active at a time. When Local AI, LM Studio, or Ollama is selected, Zush does not silently fall back to cloud analysis.

## Quality and performance

Cloud models are usually the simplest option for complex mixed folders. Local quality and speed depend on the model, file type, available memory, and Mac hardware. Test a representative small batch before assigning any mode to folder monitoring.
