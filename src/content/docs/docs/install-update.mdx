Zush runs on Mac and Windows. Install from the product page for your operating system, then use the same core AI file renaming workflow on either platform.

Quick links: [download Zush for Mac](/download/mac), open [Zush on the Mac App Store](https://apps.apple.com/app/zush/id6758432449), install with [Homebrew](https://formulae.brew.sh/cask/zush), or install [Zush from the Microsoft Store](https://apps.microsoft.com/detail/9ND4WVZSDQ3X).

## Install on Mac

Mac users can install Zush from the [Mac product page](/mac), the [direct signed .dmg download](/download/mac), the [Mac App Store listing](https://apps.apple.com/app/zush/id6758432449), or the [Homebrew cask](https://formulae.brew.sh/cask/zush) with `brew install --cask zush`. Depending on the build you choose, updates are handled by the store channel, Homebrew, or the signed direct app update flow.

Zush for Mac supports macOS 15.0 and newer. Folder access is granted by the user when files, folders, or monitored folders are selected.

## Install on Windows

Windows users install Zush from the [Microsoft Store listing](https://apps.microsoft.com/detail/9ND4WVZSDQ3X) or the [Windows product page](/windows). The Store handles package trust, installation, and updates through the standard Windows app channel.

Zush for Windows supports Windows 10 and Windows 11.

## Requirements

| Requirement | Notes |
| --- | --- |
| Memory | 4 GB minimum; more memory is recommended for local models. |
| Disk space | About 200 to 250 MB for the app, about 3.4 GB for the built-in Local AI model, or additional space for LM Studio and Ollama models. |
| Network | Required for Zush Cloud AI, BYOK, updates, and initial model downloads. Local AI modes can analyze offline after setup. |
| Built-in Local AI | Available on Mac and managed inside Zush. See the [Local AI guide](/docs/local-ai). |
| External local models | Install [LM Studio](/docs/lm-studio) or [Ollama](/docs/offline-ai) and a compatible vision model. |

## Update behavior

Store builds update through the platform store. Direct builds use the app's normal signed update path. For the best result, keep Zush current before testing new file types, [AI modes](/docs/ai-modes), or [monitored folder workflows](/docs/folder-monitoring).
