Open **Activity** to see completed renames and folder moves. You can undo an individual file or use **Undo All** to work through the saved history.

## Undo one file

<Steps>
1. Open **Activity** and find the file.
2. Check its original name and current name or location.
3. Choose **Undo** for that item.
4. Check the result in Activity or your file browser.
</Steps>

Undo restores the original filename and folder when the file and destination are available. If Zush renamed a file and later sorted it, undo can follow those steps back to the original location. Saved metadata is restored where supported.

## Undo all saved changes

Choose **Undo All** and confirm the action. This applies to the saved history, so check the confirmation before continuing.

When it finishes, Zush shows restored files and any files that still need attention. A partial result does not mean that every file failed: inspect the individual results before retrying.

## Resolve a conflict

Zush cannot restore a file to a location that another file already occupies. For eligible items, choose **Restore with New Name** to put the file back under an available name without overwriting the existing file.

Other problems can require action outside Zush:

| Problem | What to do |
| --- | --- |
| The drive or source folder is unavailable | Reconnect the drive or restore access, then retry. |
| The file was moved or deleted outside Zush | Locate or restore the file before trying again. |
| The destination is locked or not writable | Make the destination available and retry. |

<Aside type="note">
Undo uses the files that still exist on disk. Rename history is not a backup of file contents.
</Aside>

Test the Template in [AI Rename](/docs/batch-rename-files), where names can be reviewed before applying. [Monitor](/docs/folder-monitoring) and [Quick Rename](/docs/quick-rename) apply names automatically; inspect their results in Activity afterward.
