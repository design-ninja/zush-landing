## Eagle

Eagle is a paid library app for collecting and browsing visual assets. Its site says it can "preview more than 100 formats", preview fonts without installing them and play videos in the grid. You tag assets by style, project or anything else, and smart folders collect files by name, tag, color or format. Batch processing renames and tags many assets at once. It runs on macOS 10.15 or later and Windows 10 or later.

It is sold as a one-time license for two devices with later updates included; check the current price on the Eagle store, which was running a seasonal discount when we checked.

**Best for:** designers who collect a lot of references, screenshots, fonts and short clips and want to browse them visually by tag and color.

## Adobe Bridge

Adobe's product page offers Bridge as a free download. It lists metadata editing, keywords, labels and ratings, collections with filters and search, and batch rename or batch export. Previews cover Photoshop, InDesign, Illustrator, After Effects and Substance 3D files. The product page we could load did not state the macOS requirements or whether an Adobe account is needed, and Adobe's help pages refused our automated check, so confirm both on Adobe's site before you plan around it.

**Best for:** designers who already work in Photoshop or Illustrator and want ratings, keywords and batch rename in a free browser for those files.

## Pixave

Pixave is a Mac image organizer from LittleHJ. The Mac App Store lists it as free and describes tagging many images at once, keywords imported automatically, Smart Collections, iCloud Sync for libraries and batch renaming of titles and filenames. Its formats include common images such as JPEG, PNG, TIFF, PSD and HEIC, plus MOV and MP4. The developer's page adds AI files and Sketch files when Sketch is installed, and says edited versions can be saved and restored.

The latest version in the store's history is 2.3.13 from November 23, 2020, and the old pixave.com address now goes to a domain sale page. The store shows no rating summary.

**Best for:** someone who wants a light, free image library on a Mac and is fine with an app that has not been updated for years.

## Billfish

Billfish is a free asset manager from China. Its site says the personal edition is free and supports Windows and macOS 10.13 or later. It claims support for "100+" material types, search by color and by image, and filtering by several conditions. The site does not list file formats, tags, renaming or versioning, and the pages we checked give no price for the team library.

**Best for:** designers who want a free visual library on both Mac and Windows and can work with a mostly Chinese-language site.

## Do you need dedicated DAM software at all?

| Situation | Start with | Add dedicated DAM when |
|---|---|---|
| Solo designer | Project template, filenames, Finder tags | Rights, approvals, or a large reusable library become hard to track |
| Small product team | Shared source, export, handoff, and archive folders | Several people publish or approve the same assets |
| Agency | Client-level structure plus locked handoff folders | Reuse, permissions, and client approvals cross many accounts |
| Brand organization | Controlled library and naming policy | Distribution, usage rights, localization, and audit history matter |

The four apps above are personal or small-team libraries. They help you browse. Enterprise DAM platforms add permissions, approval states, rights management and audit trails, and those only pay off when several people publish the same assets.

A quick way to decide: if you spend more time looking for a file than choosing between files, fix names and folders first. If you mostly scroll through inspiration and references to pick one, a library app like Eagle earns its place.

## The Finder setup in short

Most of this is covered in more detail elsewhere, so here is the short version.

**Folders.** Keep one template per project and separate source files from exports. The [client folder guide for freelancers](/blog/organize-client-files-freelancers-mac) has the full structure. The layout changes a little by role:

```
ui-project/          brand-name/          marketing/
  source/              logos/               2026-q1/
  exports/             typography/            spring-launch/
  references/          color/                   source/
  handoff/             templates/               exports/
  archive/             guidelines/              copy/
                       collateral/
```

UI work splits by function, so a developer always knows exports live in `exports/`. Brand work splits by asset type. Marketing splits by quarter and campaign, because those assets are short-lived and pile up fast.

**Names.** Use lowercase words joined by hyphens, put the most searchable word first, use `YYYY-MM-DD` dates when order matters, and add `v2` or `v3` instead of words like "new" or "latest". For example: `checkout-screen-mobile-dark-v2.png`, `acme-logo-horizontal-white.svg`, `icon-cart-24px.svg`. [File Naming Conventions](/blog/file-naming-conventions-best-practices) explains each rule, and [Naming Blocks](/blog/naming-blocks-file-naming-guide) shows how to build the pattern in Zush.

**Tags and Smart Folders.** Use named Finder tags for status, so the tag name says what it means even if two people read colors differently:

| Tag name | Use it for |
|---|---|
| In review | Sent to a client or teammate, waiting for feedback |
| Approved | Signed off and safe to hand off |
| Reference | Inspiration or research, not for delivery |

You can give each tag a color too, but search by the name. A Smart Folder such as "tag is Approved, kind is image, modified in the last 30 days" shows current deliverables without moving them. The [Finder tags guide](/blog/finder-tags-guide-organize-files-mac) covers setup.

## Version control for design files

How you track versions depends on the file type.

**Figma files.** Figma keeps version history for every file, so you do not need copies like `checkout-flow-v1.fig` and `checkout-flow-v2.fig`. You can name a version, add a description and restore an earlier one, and restoring does not delete the current state. Figma's help center says Starter plan and Drafts users see only 30 days of history, and paid plans see the full history. Branching, where you work in a copy and then review and merge it back, is listed for Organization, Enterprise, Government and Education (K-12) plans. If you are on Starter, name a version at each milestone and export a PDF or image at sign-off so the record outlives the 30 days.

**PSD, Sketch and other local files.** These have no shared history unless your tool provides one, so put the version in the filename and keep one current file in `source/`:

```
source/
  spring-campaign-hero-v3.psd
archive/
  spring-campaign-hero-v1.psd
  spring-campaign-hero-v2.psd
```

For assets that change weekly, such as social templates, a date works better than a number: `spring-campaign-hero-2026-03-22.psd`.

**Exports.** Name every export with the feature, the state and the size or density: `checkout-button-primary-hover.svg`, `app-icon-1024x1024.png`, `facebook-ad-spring-promo-v2.jpg`. An export cut off from its source file is the one most likely to end up as `export-2.png`.

Three rules hold for all of them:

- Keep one current version of each asset in a folder. Move replaced versions to `archive/`.
- Do not trust modification dates. Copying, syncing and moving can change them.
- Use the Approved tag, not a word in the filename, to mark signed-off work.

## Developer handoff

Developers need to map a filename to a component without asking you. That means a single handoff folder with only current assets, clear formats (SVG for icons, WebP or PNG for images, PDF for specs) and labeled density variants.

```
handoff/
  icons/
    icon-search-24.svg
    icon-cart-24.svg
  images/
    hero-homepage-1200x630.webp
    hero-homepage-600x315.webp
  specs/
    checkout-flow-annotations.pdf
    color-tokens.json
```

Delete replaced files from `handoff/` when you add new ones. A handoff folder with old and new versions side by side causes more questions than no folder at all. Before you send it, show one filename to a teammate and ask what it is. If they need to open the file to answer, rename it.

For screen recordings and b-roll that go along with a handoff, see [organizing screen recordings with AI](/blog/organize-screen-recordings-broll-ai).

## Where Zush fits

Zush is not a library app. It has no boards, no visual grid and no moodboards, so it does not replace Eagle or Bridge if you browse references visually. What it does is give files names that describe them, so Finder, Spotlight and any of the apps above can find them.

What it does for design files, according to the Zush docs and changelog:

- On Mac, it names Figma, Sketch and PSD files by what the design shows. Sketch support for this was added in Mac 3.25.0 on November 22, 2026. Figma and Sketch files are Mac-only inputs.
- Since Mac 3.24.0, you can select files in Finder, right-click, choose **Rename with Zush**, then **Smart** or one of your templates. Turn it on in Zush Settings under **Quick Rename**. It does not work for files in iCloud Drive or other cloud drives, which you add to AI Rename instead. See [Quick Rename](/docs/quick-rename).
- Monitor watches a folder such as your exports or screenshots folder and renames new files as they arrive.
- Naming Blocks let you fix the pattern, such as client, asset type and date, and every name in a batch is shown before you apply it. Applied batches can be undone from Activity.

Pricing: 50 AI renames free with no account or card, then $10 a month or $48 one-time. The one-time license covers 3 devices, Mac and Windows mixed, and includes the Zush cloud AI, so you do not need your own API key. Eagle's license buys a browsing library with pattern-based batch rename; Zush's buys names written from each file's content. The two can work together: Eagle to browse, Zush to name files before they reach the library.

## A 30-minute setup for your next project

1. **Create the folders**: `source`, `exports`, `references`, `handoff` and `archive`.
2. **Write one naming pattern**: project, asset type, description, then version or date.
3. **Create three Finder tags**: In review, Approved and Reference.
4. **Move old versions**: keep one current file in `source` and move the rest to `archive`. For Figma files, name a version instead.
5. **Prepare handoff**: export one asset and check that a developer can identify it without opening it.
6. **Automate the inflow**: point Zush Monitor only at the export or screenshot folder where weak names keep appearing.

Run this on the next active project, not the whole archive. Once it works, copy the template to older projects when you reopen them.

## FAQ

### Is Pixave still maintained?

The newest version in its Mac App Store history is 2.3.13 from November 23, 2020, and pixave.com now redirects to a domain sale page. It is still listed as free, but plan for no updates.

### Do I need dedicated DAM software as a freelance designer?

Usually not. A folder template, a naming rule and Finder tags cover most freelance work. Add a library app like Eagle when you browse large collections of references visually, and an enterprise DAM only when several people need permissions, approvals and usage rights.

### How do I version Figma files without duplicating them?

Use Figma's version history: name a version at each milestone and restore from the history when needed. Starter plan and Drafts keep 30 days of history, and paid plans keep the full history, so on Starter export a PDF at sign-off as a permanent record.
