Quick answer: use cloud AI when you want the easiest setup and the strongest names on everyday files. Use your own API key (BYOK) when you rename in high volume and want to pick and pay the provider yourself. Use a local model through Ollama or LM Studio when files must not leave your computer and you have the hardware for it. In [Zush](/) all four routes are in the same app, so you can pick per folder.

AI file renaming is no longer a single technical choice. Zush exposes four AI routes: Zush Cloud AI, BYOK, Ollama, and LM Studio. They can all produce better filenames than rules alone, but they optimize for different constraints.

This guide compares the four routes from a practical desktop workflow perspective: privacy, speed, cost, quality, setup effort, and when each one fits. For the Ollama setup path, start with the [Ollama Setup Guide](/docs/offline-ai). For the product overview, see [File Renamer for Mac and Windows](/). For the current Mac release, see [AI file renamer for Mac](/mac).

## The four AI routes

| Mode | What it means | Best fit |
|---|---|---|
| Cloud AI | Zush sends supported files to managed Zush Cloud AI. 50 free renames, unlimited with PRO | Easiest setup and strong everyday quality |
| BYOK | You connect your own provider key for cloud AI | Your own provider account and direct provider billing |
| Ollama | Zush connects to an Ollama model running on your device | Private processing for supported files and offline workflows |
| LM Studio | Zush connects to a compatible local model served by LM Studio | Local model choice through a desktop model manager |

All four routes are useful. The mistake is treating them as interchangeable. A managed cloud model, an API-key workflow, and local models served by Ollama or LM Studio have different strengths.

## Privacy

Privacy is where local AI has the clearest argument. With Ollama or LM Studio selected in **Settings → AI Modes**, supported file analysis runs through the local model on your device instead of [Zush](/) cloud or a third-party AI provider.

Cloud AI and BYOK can still be appropriate for many files. They are convenient, fast, and often stronger. But if you are renaming sensitive client screenshots, contracts, scans, invoices, or internal research, local processing may be the better default.

For scanner and fax folders in a clinic, the [medical records file-renaming workflow](/for-medical) shows how local AI and organization-controlled BYOK fit record-specific Templates, preview, and undo.

The practical privacy ladder looks like this:

| Privacy preference | Recommended mode |
|---|---|
| Sensitive folders should stay local | Ollama or LM Studio |
| I choose the cloud provider and manage billing | BYOK |
| I want the simplest workflow | Cloud AI |

For full data handling language, read the [privacy policy](/privacy-policy).

## Speed

Cloud AI is usually the fastest path for large batches because remote providers run on specialized infrastructure. BYOK is also cloud-based, so speed depends on the provider you choose. Local AI speed depends on your hardware, the model size, and what else your computer is doing.

Local models can feel responsive on a modern Mac with small vision models. They can also feel slow if you ask a small laptop to process a huge folder while other apps are open.

Use this rule:

- Use Cloud when speed matters and the files are not sensitive.
- Use BYOK when you process many files and want cloud throughput through your own provider account.
- Use Ollama when local processing matters more than maximum speed.

For ongoing folder workflows, see [Folder Monitoring for Automatic File Renaming](/blog/folder-monitoring-automatic-file-renaming).

## Quality

Quality depends on the model. Cloud models tend to be stronger at complex screenshots, messy documents, and ambiguous images. Local vision models are improving quickly, but small models can still produce generic names or miss important context.

For file renaming, you do not need a poetic caption. You need names that are:

- accurate
- short
- searchable
- consistent with your naming pattern
- safe to review before applying

That last point matters. A good AI renamer should show a preview and keep rename history. Zush does both, so you can compare modes without committing every suggestion blindly. The [safe batch rename guide](/blog/how-to-safely-batch-rename-files) separates what to verify before applying from the recovery options you need afterward.

If local names are weak, adjust the prompt or try another compatible model. The current Zush Ollama default is [`qwen3.5:4b`](https://ollama.com/library/qwen3.5); select it under **Settings → AI Modes → Ollama**.

## Cost

The cost model is different for each mode.

Managed PRO is the simplest. Zush includes 50 free AI renames with no account, card, or API key, then PRO unlocks unlimited renames for $10/month or $48 one-time. The one-time license covers every mode, including Zush Cloud AI, plus all future updates and up to 3 Mac or Windows devices. You do not manage provider billing.

BYOK shifts cost to your provider account. You bring an API key from a supported provider and pay the provider directly. This is often the best option for users who want cloud quality through their own provider account. For the full walkthrough, read [BYOK AI File Renaming with Your Own API Key](/blog/byok-ai-file-renaming-unlimited) and [BYOK Setup Guide](/docs/byok).

Local AI with Ollama has no per-rename AI provider bill once the model is installed, but it uses your hardware, memory, battery, and disk space. The cost is not a cloud invoice. The cost is local compute and setup time.

| Mode | Direct AI cost | Hidden cost |
|---|---|---|
| Cloud AI | 50 free renames, then PRO at $10/month or $48 one-time | Internet required |
| BYOK | Provider API billing | API key setup and provider account management |
| Ollama | No provider request per local rename | Local compute, model storage, slower batches on weaker hardware |

## Setup effort

Cloud AI is nearly zero setup. Install Zush, choose files, preview names, rename.

BYOK requires creating an API key, choosing a provider, and testing the connection. It is still straightforward, but there is an account and billing layer.

Ollama requires local setup:

1. Install Ollama from the official [download page](https://ollama.com/download).
2. Pull a vision model.
3. Confirm Ollama is running.
4. Select the model in Zush.
5. Test before using large folders.

For Mac-specific instructions, read [How to Rename Files with Ollama on Mac](/blog/rename-files-with-ollama-mac). Ollama and LM Studio also work with Zush for Windows; the [local AI docs](/docs/local-ai) cover both platforms. For audio and video, local speech recognition can feed spoken content into filename suggestions without uploading the recordings: through Ollama or LM Studio on Mac, and as an optional on-device speech download on Windows.

Hardware matters more for local models. In cloud mode Zush needs about 4 GB of RAM and a ~200 MB app on macOS 15+ or Windows 10/11. A local vision model needs far more memory and disk space, which is the cost you trade for keeping files on the machine.

## Which mode should you choose?

### Choose Cloud AI when:

- you want the least setup
- you rename normal everyday files
- speed and quality matter more than local processing
- you are using the free tier or managed PRO cloud comfortably

### Choose BYOK when:

- you process hundreds or thousands of files
- you want cloud model quality through your own provider account
- you already have a provider account
- you want direct billing visibility

### Choose Ollama or LM Studio when:

- folders contain sensitive analysis content
- internet access is limited or unavailable
- you want provider-independent processing for supported files
- you are comfortable installing and managing a local model

Many users will use more than one mode. That is the point. Use Cloud for normal cleanup, BYOK for high-volume cloud work, and Ollama for folders where local processing is the priority.

## FAQ

### Is local AI better than cloud AI for file renaming?

Not universally. Local AI is better when privacy and offline processing matter, because supported analysis stays on your computer. Cloud AI is usually easier to set up and often gives stronger names for difficult screenshots, scans, and ambiguous images, because larger models run on remote hardware. Many people use both: cloud for everyday downloads and a local model for confidential folders.

### Where are my files processed in each Zush mode?

With Zush Cloud AI, supported files are analyzed by Zush's managed cloud service. With BYOK, they go to the provider whose API key you connected, under that provider's terms. With Ollama or LM Studio, analysis runs through the local model on your Mac or Windows PC, and Zush does not silently fall back to the cloud while a local mode is selected. See the [privacy policy](/privacy-policy) for details.

### Does BYOK mean files stay local?

No. BYOK is still cloud processing. The difference is that you use your own provider API key, choose the provider, and pay it directly for each request. That can suit high-volume work or company accounts with their own data agreements. For processing that stays on your device, select Ollama or LM Studio under **Settings → AI Modes** instead.

### Which is cheapest for renaming thousands of files?

A local model has no per-file bill once it is installed, but it costs hardware, time, and setup. BYOK charges per request at your provider's rates. Zush PRO at $48 one-time includes unlimited renames with Zush Cloud AI, BYOK, Ollama, and LM Studio, so a large batch on the managed cloud adds no extra cost. Many other one-time renamer licenses include only your own key or a local model.

### Can I switch modes later?

Yes. The mode is a setting, not a separate purchase, so you can use the one that fits each folder. A practical split is local AI for sensitive files, Zush Cloud AI for speed on everyday files, and BYOK for high-volume cloud work through your own provider account. Rename History and undo work the same way in every mode.

### Is local AI supported on Windows?

Yes. Zush for Windows connects to Ollama and LM Studio the same way the Mac app does, and offers an optional on-device speech model for audio and video. Install a vision-capable model, select the local mode in AI settings, and test on a small copied folder first. The [local AI docs](/docs/local-ai) cover setup on both platforms, and the [Windows page](/windows) lists current requirements.
