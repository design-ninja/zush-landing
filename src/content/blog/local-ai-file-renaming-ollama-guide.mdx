To rename files with a local AI model on Windows, install Ollama or LM Studio, open **AI Modes** in [Zush for Windows](/windows), select that server and a vision-capable model, then click **Test**. While Ollama or LM Studio is selected, supported file analysis runs on your PC with no silent switch to cloud AI, and the first 50 AI renames are free; PRO costs $10 a month or $48 once and removes the limit.

This guide covers the Windows setup only. To decide between cloud and local first, read [Cloud AI vs Local AI File Renaming](/blog/cloud-vs-local-ai-file-renaming). On a Mac, follow [Use Ollama to rename files on Mac](/blog/rename-files-with-ollama-mac).

## What local mode means in Zush

Zush has four AI modes: Zush Cloud AI, BYOK, Ollama, and LM Studio. Only one is active at a time, and it applies everywhere in the app: AI Rename, Quick Rename, and Monitor.

With Ollama or LM Studio selected, Zush prepares a preview, extracted text, or metadata from each file and sends it to the server on your own PC. The default addresses are `http://127.0.0.1:11434` for Ollama and `http://127.0.0.1:1234` for LM Studio. If the local server is down, the rename fails instead of quietly going to the cloud. Licensing and update checks can still use the network. Local models do not get raw audio for transcription, so recordings are named from their text, metadata, and visual previews ([audio and video notes](/docs/audio-video)).

One Ollama detail matters here: Ollama also offers cloud models, which run on Ollama's servers. Their names end in `:cloud`. If you want analysis to stay on your PC, install a model without that suffix.

## Requirements on Windows

| | Zush for Windows | Ollama for Windows | LM Studio on Windows |
|---|---|---|---|
| Windows version | Windows 10 or 11 | Windows 10 22H2 or newer, Home or Pro | Not listed; x64 and ARM (Snapdragon X Elite) supported |
| Memory | 4 GB minimum; more recommended for local models | Not listed | At least 16 GB recommended |
| CPU | Not listed | Not listed | AVX2 required on x64 |
| GPU | Not listed | NVIDIA driver 551.61 or newer for NVIDIA cards; ROCm v7 or a Vulkan-capable Radeon driver for AMD | At least 4 GB of dedicated VRAM recommended |
| Disk | About 200 to 250 MB for the app | At least 4 GB for the install, plus space for models | Not listed |

Sources: [Zush install requirements](/docs/install-update), [Ollama Windows docs](https://docs.ollama.com/windows), [LM Studio system requirements](https://lmstudio.ai/docs/app/system-requirements). Ollama models can take tens to hundreds of GB; the `OLLAMA_MODELS` environment variable moves them to another drive.

## Set up Ollama on Windows

You don't need PowerShell for this route.

1. Open Zush **Settings → AI Modes** and choose **Ollama**.
2. If you see **Download Ollama**, click it. It opens the official download page. Run the installer (it installs to your user folder and doesn't need administrator rights), then return to Zush.
3. If you see **Start Ollama**, click it and wait for the local server to come up.
4. If no model is installed, Zush shows **Download** with the suggested model's name. Click it and watch the progress. **Cancel** stops the download.
5. When the download and connection check finish, Zush selects the model and turns on Ollama mode.
6. If you already had models installed, Zush shows a **Model** picker instead. Pick one that can read images (the picker labels them), then click **Test**.

To use a different model, install it yourself in PowerShell with `ollama pull` followed by the model name, then refresh the model list in Zush. See the [Ollama setup docs](/docs/offline-ai) for alternatives and their commands.

## Set up LM Studio on Windows

1. Install [LM Studio](https://lmstudio.ai/) and download a vision-capable model in it.
2. In Zush, open **AI Modes** and choose **LM Studio**. If LM Studio isn't running, start it from Zush. Since Windows version 3.19.2.0, starting LM Studio from Zush also starts its local server. You can also turn on **Start Server** in LM Studio's **Developer** tab.
3. Keep the host at `http://127.0.0.1:1234` unless you changed it in LM Studio.
4. Refresh the model list and pick a model. Zush lists only models that LM Studio reports as vision-capable.
5. Click **Test** and wait for **Connection OK**.

## Choosing a model

A file renamer needs a model that can read images such as screenshots, scans, and document previews. Text-only models can't, so both Zush pickers filter or label vision models.

Start with what Zush offers. In Ollama mode, that's the model on the Download button and the **Recommended models** link; in LM Studio, it's whatever vision model you've loaded. If you want to try others, the [Ollama setup docs](/docs/offline-ai) and [LM Studio docs](/docs/lm-studio) list options. Families such as Qwen-VL and Gemma 3 are examples of vision-capable models, not a Zush default.

Smaller models answer faster and use less memory; larger ones may describe files better if your PC can hold them. Windows versions 3.18.0.0 and 3.19.5.0 made small local models more reliable, so a small model is a fair first try.

## Your first local batch

Don't point a new model at your whole archive. Test it first:

1. Pick a folder with 10 to 20 files.
2. Mix the types: screenshots, photos, and a few PDFs.
3. Add them to **AI Rename** and run the analysis with your local mode selected.
4. Review every proposed name before you click Rename.
5. If names are too long or too vague, adjust the Template or custom prompt and run it again.
6. Move to larger folders only once the names match your style.

Names like these are a realistic target for a good vision model (examples, not guaranteed output):

| Original filename | A local model might suggest |

## Using a local model with Monitor and File Explorer

Once the batch looks right, the same AI mode covers automatic renaming. Both options apply names without a preview, so test the Template in AI Rename first:

- **Monitor** watches folders such as Downloads or Screenshots and renames new files with the Template you assign. It applies names without a review step, and Zush has to be running. Keep Ollama or LM Studio running as well, because Zush won't switch to the cloud when the local server is off. See [folder monitoring](/docs/folder-monitoring).
- **Rename with Zush** in the File Explorer right-click menu was added in Windows version 3.19.5.0 and is available in the Microsoft Store version. Select files, right-click, choose **Rename with Zush**, then **Smart** or one of your Templates. It renames in the background with your current AI mode. The keyboard shortcut does the same for up to 10 selected files at a time. See [Quick Rename](/docs/quick-rename).

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Zush shows **Start Ollama**, or Test fails | The Ollama server isn't running | Click **Start Ollama**, or open Ollama from the Start menu |
| LM Studio Test fails | LM Studio's server is off, or the host was changed | Start LM Studio from Zush or turn on **Start Server** in its Developer tab; check the host is `http://127.0.0.1:1234` |
| The model list is empty | No model is installed or loaded, or the model can't read images | Download or load a vision-capable model, then refresh the list in Zush |
| A model you installed is missing | The list wasn't refreshed, or the host address is wrong | Click refresh; in PowerShell, `ollama list` shows what Ollama has installed |
| Model download fails | Connection dropped or the drive is full | Free up space (or move models with `OLLAMA_MODELS`) and try again |
| Renaming is very slow | The model runs on the CPU or is too large for your memory | Try a smaller vision model, close memory-heavy apps, and check your GPU driver meets Ollama's minimum |
| A file type fails | The model can't read that input | Test a supported file with a vision model and check the server logs (`%LOCALAPPDATA%\Ollama\server.log` for Ollama) |

More fixes are in the [local AI docs](/docs/local-ai).

## Limits

- The free plan includes 50 AI renames, shared across all four modes. A local model doesn't give you extra free renames.
- A batch in AI Rename can hold up to 1,000 files on Free too, but only the first 50 are renamed. The rest wait as **Awaiting PRO**.
- PRO costs $10 a month or $48 one-time and removes the limit in every mode ([pricing](/pricing)).
- Local quality depends on the model, the file, and your hardware. For complex mixed folders, cloud models are usually the simpler option; [local AI file organizers compared](/blog/local-ai-file-organizers-compared) covers how other apps handle this.

## FAQ

### Do I need to open a port in Windows Firewall?

No, not for this setup. Zush and the server run on the same PC and talk through the local address `127.0.0.1`. Ports and firewall rules only matter if you want other computers on your network to reach the server, which Zush doesn't need.

### Do I need a GPU?

No, but it helps. Ollama warns that large models are slow without a strong GPU. It supports NVIDIA and AMD Radeon cards on Windows, and LM Studio recommends at least 4 GB of dedicated VRAM. On CPU only, use a small vision model.

### Does local AI work in both the Microsoft Store and portable versions?

Ollama and LM Studio modes are part of Zush for Windows. The File Explorer **Rename with Zush** menu is listed for the Microsoft Store version. The portable ZIP is updated by downloading a newer release ([install and update](/docs/install-update)).

### Does it work offline after setup?

Yes for the analysis. You need internet to install Ollama or LM Studio and to download a model. After that, local modes can analyze files offline. Licensing and update checks use the network when it's available.

### Can I switch back to cloud AI later?

Yes. Choose another mode in **AI Modes** at any time. Your Templates keep their naming and sorting settings, because they don't store an AI provider. See [AI modes](/docs/ai-modes).
