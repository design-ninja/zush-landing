“RenameClick”是“macOS”和“Windows”的本地优先桌面应用程序。其核心卖点是隐私：一次性本地模型下载后，其内置的 Qwen3-VL 提供程序可以在没有 API 密钥或互联网连接的情况下处理设备上的文件。它还支持用于本地服务器工作流程的 LM Studio 和“Ollama”，当您显式连接云 API 密钥时，还支持 OpenAI、Google Gemini 和阿里云 Qwen。 RenameClick 指出云提供商在 Mac App Store 版本中不可用；如果这些提供商很重要，请使用直接下载。

## 格式支持

### 对于真正的混合文件夹，“Zush”范围更广

Zush 支持 RAW 照片格式、设计文件、音频、视频、iWork 文件、Office 文件、字幕和数据/文本格式。如果您的文件夹很乱，那么这就是实际优势，因为它们是真实的：手机照片旁边是屏幕截图，PDF 旁边是相机 RAW，Keynote/Pages 文档旁边是 Figma/Sketch/PSD 文件，会议记录旁边是视频文件。音频不再是这一差距的一部分——“RenameClick”现在可以处理常见的音频格式——但 RAW、设计文件、“iWork”和视频仍然是。

### “RenameClick”涵盖常见图像、广泛的文档列表，现在还包括音频

“RenameClick”很好地涵盖了常见的图像和文档工作流程 - JPEG、PNG、GIF、WebP、AVIF、BMP、SVG、HEIC、HEIF、TIFF，以及 PDF、DOC/DOCX、TXT、Markdown、CSV、RTF、ODT、JSON、XML、YAML、HTML、日志、SQL、字幕和日历/联系人文件 - 并且它添加了带有本地语音的音频（MP3、WAV、FLAC、M4A、AAC）转录。它还具有有用的文档处理详细信息：文本 PDF 和 Office 文档的文本提取、扫描 PDF 的视觉回退以及可配置的文档文本修剪限制。

差距在于媒体和设计格式。 RenameClick 的文档没有列出相机 RAW 格式或 Sketch/Figma/PSD 等设计文件，并且明确表示不支持视频文件、存档和可执行文件。如果这些格式很重要，“Zush”更安全。

## 本地人工智能是平等的；命名控制不是

这两种产品都可以运行本地模型，因此离线处理并不是独特的优势。 “RenameClick”在下载多 GB 后捆绑模型； “Zush”连接到“Ollama”。更重要的区别是工作流程的其余部分：“Zush”记录了现成的“Templates”、145+“Naming Blocks”、“Custom AI Blocks”、更丰富的本地化和元数据控制以及持久的“Rename History”。

如果您更关心云提供商的选择和大容量的“BYOK”，“Zush”会胜出。 Zush 通过 BYOK 支持 Gemini、OpenRouter、OpenAI 和 Claude，密钥存储在本地，当本地处理优先时，它通过 Ollama 支持离线 AI。 OpenRouter 和 Claude 是著名的“Zush”侧选项；内置的Qwen3-VL、阿里云Qwen和LM Studio是“RenameClick”端选项。

实际取舍很简单：看重命名深度、恢复细节、混合文件覆盖和提示词驱动的文件夹分类，就选 Zush。只有当 AI Search 工作区比缺少 RAW、设计文件、iWork 和视频支持更重要时，才考虑 RenameClick。

## 自动化和组织

这两种工具都可以监视文件夹，但它们强调不同的结果。

Zush 的文件夹监控以可复用的 Templates 和 Naming Blocks 自动进行 AI 重命名为核心。开启分类的模板还会把每个新文件移到由你的日常语言文件夹规则或 Auto 选定的文件夹，Monitor 会继续使用它创建的文件夹。适合“下载”、扫描仪文件夹、截图和定期更新的客户文件夹。

“RenameClick”自动流程更像是一个规则行系统。每行可以有自己的源文件夹、目标文件夹、命名格式、自定义指令、语言、排序预设、递归设置和自动应用设置。它可以同时运行多行，在处理之前等待文件变得稳定，避免目标文件夹内的循环处理，并在免费计划积分用完时暂停。

如果你的目标是统一命名文件，并按你用自己的话描述的规则归档，Zush 是文档更完善的方案。如果固定的类别列表或与已有顶层文件夹匹配就足够，可以考虑 RenameClick；更窄的格式支持仍是这一选择的代价。

## 搜索、元数据和检索

“Zush”通过生成有意义的文件名、添加“Finder”标签以及编写“Spotlight”友好的元数据来帮助检索。这适合已经搜索过“Finder”/“Spotlight”并希望文件名包含最重要上下文的 Mac 用户。

“RenameClick”添加了一个单独的 AI 搜索工作区。它允许您按内容含义进行搜索，而不仅仅是文件名关键字。例如，即使原始文件名是“scan_001.pdf”，发票搜索也可以匹配 PDF 扫描。 AI 搜索对于重命名/移动目的是只读的，但它可以显示文件、排除结果或将项目移至垃圾箱。

对于在混乱的文件夹中进行发现，“RenameClick”的人工智能搜索是一个有意义的差异化因素。为了将文件转变为跨操作系统的长期可搜索资产，“Zush”的文件名+标签+元数据工作流程是更好的日常层。

## 常问问题

### “RenameClick”比“Zush”便宜吗？

Zush 为每月10美元或终身48美元。RenameClick 为每月8美元或终身36美元，另加增值税。

### ‘RenameClick’可以离线工作吗？

是的。 RenameClick 是本地优先的。下载本地模型后，内置的本地提供程序可以在没有互联网、没有 API 密钥、也没有 API 成本的情况下运行。云提供商需要互联网和您自己的提供商密钥。

### ‘Zush’可以离线工作吗？

是的，通过“Ollama”的离线人工智能模式。不同的是Zush没有捆绑自己的本地模型作为默认路径；您设置“Ollama”并选择兼容的本地型号。

### ‘RenameClick’支持RAW照片吗？

“RenameClick”的公共支持文件列表不包括相机 RAW 格式，如 CR2、CR3、NEF、ARW、DNG、ORF、RAF、RW2、PEF、SRW 或 SR2。 Zush 明确支持这些 RAW 格式。

### RenameClick 支持视频或音频文件吗？

音频有，视频没有。它的文档现在列出了带有本地语音转录的 MP3、WAV、FLAC、M4A 和 AAC，而视频文件（`.mp4`、`.mov`、`.mkv`、`.webm`）、其他音频编解码器、存档和可执行文件明确不受支持。 “Zush”支持 16 种视频格式及其音频列表。

### 哪个具有更好的文件夹自动化功能？

大多数文件夹选 Zush。两款应用都能重命名新文件并把它们移入文件夹。Zush 按日常语言文件夹规则或 Auto 分类，复用已有文件夹，并用 Templates 和 Naming Blocks 命名文件。RenameClick 的 Auto Flow 按预设类别或最多 50 个已有顶层文件夹分类，并可选择复制而不是移动。
