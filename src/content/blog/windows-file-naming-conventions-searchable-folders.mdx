Windows file naming rules are the limits Windows puts on file and folder names: no `< > : " / \ | ? *` characters, no reserved device names such as `CON` or `NUL`, no space or period at the end, and a classic path limit of 260 characters. Windows also treats names as case-insensitive, and File Explorer sorts the digits in a name by their numeric value.

The rules below come from Microsoft's documentation, linked in each section. Breaking one usually shows up as an error when you save, a file File Explorer can't handle, or a OneDrive sync failure. For general conventions such as dates, separators and version numbers, read the [file naming conventions guide](/blog/file-naming-conventions-best-practices). This page covers what is specific to Windows.

## Characters Windows does not allow

Microsoft's [Naming Files, Paths, and Namespaces](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file) reference lists nine reserved characters that can't appear in a file or folder name:

`<` `>` `:` `"` `/` `\` `|` `?` `*`

Control characters are also out: the NUL character (value 0) and the characters with values 1 through 31. Anything else in the current code page is allowed, including Unicode and accented letters. Spaces, hyphens, underscores and parentheses are all valid.

Dates and times are the usual trap. `11/23/2026` contains slashes, and `14:30` contains a colon. Write `2026-11-23` and `14-30` instead.

## Reserved names: CON, PRN, AUX, NUL, COM and LPT

These names are reserved for devices and can't be used as file names: `CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9`, and `LPT1` to `LPT9`. Microsoft also lists `COM¹`, `COM²`, `COM³`, `LPT¹`, `LPT²` and `LPT³`, because Windows reads the superscript digits as numbers.

An extension does not help. Microsoft notes that `NUL.txt` and `NUL.tar.gz` are both equivalent to `NUL`. In practice this catches short abbreviations: `con.docx` for "conference" or `aux.pdf` for "auxiliary". A longer name such as `con-notes.docx` is fine, because the rule covers the exact name followed by an extension.

## No trailing spaces or periods

Microsoft's rule is direct: don't end a file or folder name with a space or a period. The file system underneath may accept such a name, but the Windows shell and user interface do not, so a name like that created by a script may not work in File Explorer.

A period at the start is fine. `.temp` is a valid name.

## How long can a Windows file name be?

The limit is on the full path, not only the name. In the Windows API, [MAX_PATH](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation) is 260 characters: the drive letter, a colon, a backslash, up to 256 characters of folders and file name, and an invisible terminating null character.

Each single component, meaning one folder name or the file name, has its own limit reported by the volume. Microsoft says this value is commonly 255 characters. Apps that use the `\\?\` prefix with the Unicode APIs can reach paths of about 32,767 characters.

A deep folder tree is the usual cause. `C:\Users\you\OneDrive - Company\Clients\Northwind\2026\Contracts\Signed\...` uses a large share of the 260 characters before the file name starts.

### How to enable long paths in Windows 10 and 11

Starting with Windows 10, version 1607, you can remove the MAX_PATH limit for many file functions:

- Set the registry value `LongPathsEnabled` to `1` (type `REG_DWORD`) under `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem`, or
- Enable the Group Policy **Computer Configuration > Administrative Templates > System > Filesystem > Enable Win32 long paths**.

A reboot may be needed. The catch is that this only affects apps whose manifest declares them `longPathAware`. Microsoft states that this "isn't a change that will affect all applications." If other people or other programs open the files, keep paths under 260 characters.

## Report.pdf and report.pdf are the same name

Microsoft's guidance is to not assume case sensitivity: `OSCAR`, `Oscar` and `oscar` count as the same name. NTFS can support case-sensitive names, but that is not the default. On a normal Windows folder you can't keep `Report.pdf` and `report.pdf` side by side, so use a real difference such as a version number or date.

## How File Explorer sorts numbers

By default, File Explorer sorts file names by increasing number value, so `file2` comes before `file10`. The policy reference for [Turn off numerical sorting in File Explorer](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-windowsexplorer#nostrcmplogical) gives the example `3 < 22 < 111`. If an administrator enables that policy, Explorer sorts digit by digit instead: `111 < 22 < 3`, the way Windows 2000 and earlier did.

Zero-padding works in both modes. `scan-002.pdf` and `scan-010.pdf` sort correctly whether the comparison is numeric or plain text, and so do tools outside Explorer that compare characters one by one. The same reasoning is why `YYYY-MM-DD` dates sort in date order.

## OneDrive and SharePoint naming restrictions

Microsoft's [OneDrive and SharePoint restrictions](https://support.microsoft.com/en-us/office/restrictions-and-limitations-in-onedrive-and-sharepoint-64883a5d-228e-48f5-b3d2-eb39e07630fa) block the same nine characters as Windows. They add a few names Windows itself accepts:

- `.lock`, `_vti_` and `desktop.ini`
- `COM0` and `LPT0`, along with the usual `CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9` and `LPT1` to `LPT9`
- any file name starting with `~$`
- names with a leading or trailing space

The OneDrive sync app can rename some of these files for you. Per [Why has my filename changed?](https://support.microsoft.com/onedrive/why-has-my-filename-changed), it replaces each invalid character with an underscore. Path length limits vary by app and Office version, and Microsoft documents them separately.

## Windows naming rules at a glance

| Rule | Example that fails | Fix |
| --- | --- | --- |
| No reserved characters | `invoice 11/23/2026.pdf` | `invoice 2026-11-23.pdf` |
| No colon in times | `call-notes 14:30.docx` | `call-notes-14-30.docx` |
| No reserved device names | `con.docx`, `nul.txt` | `conference-notes.docx` |
| No trailing space or period | `meeting-notes.` | `meeting-notes.txt` |
| Full path under 260 characters | a 280-character path in a deep folder tree | shorter folder names, fewer levels |
| Names are case-insensitive | `Report.pdf` and `report.pdf` in one folder | `report-v1.pdf`, `report-v2.pdf` |
| Pad numbers to one width | `scan-2.pdf`, `scan-10.pdf` | `scan-002.pdf`, `scan-010.pdf` |
| OneDrive blocks `~$` and leading spaces | `~$budget.xlsx`, ` invoice.pdf` | `budget.xlsx`, `invoice.pdf` |

## How to search by file name in File Explorer

Windows Search uses [Advanced Query Syntax](https://learn.microsoft.com/en-us/windows/win32/search/-search-3x-advancedquerysyntax) (AQS). You type `property:value` into the File Explorer search box to narrow results. Microsoft's [AQS keyword reference](https://learn.microsoft.com/en-us/windows/win32/lwef/-search-2x-wds-aqsreference) lists these properties for all file kinds:

- `filename:` or `file:` for the file name
- `ext:` or `fileext:` for the extension, as in `ext:.pdf`
- `datemodified:` or `modified:`, as in `modified:last week`
- `kind:`, `size:` and `folder:`

Some queries that work with descriptive names:

- `filename:northwind ext:.pdf`
- `filename:contract modified:last week`
- `filename:invoice NOT filename:draft`
- `"purchase order"` for an exact phrase

`AND`, `OR` and `NOT` must be uppercase. Two dots set a range, as in `date:11/13/21..11/15/21`. In Windows 7 and later, keywords are recognized in the Windows display language only, so `filename:` works on English Windows.

A `filename:` search only matches words in the name. A file called `scan0042.pdf` gives search nothing to work with.

## Naming patterns that stay searchable

Combine the Windows limits with a few habits:

- Put the words you will search for in the name: client, vendor, document type.
- Write dates as `YYYY-MM-DD`. They contain no slashes and sort in date order.
- Pad sequence numbers to the same width.
- Keep folder names short so the full path stays well under 260 characters.

A pattern such as `YYYY-MM-DD_client_document-type.ext` gives `2026-11-23_northwind_purchase-order.pdf`: underscores between fields, hyphens inside a field, and no reserved characters. The [file naming conventions guide](/blog/file-naming-conventions-best-practices) has more templates.

## FAQ

### Which characters are not allowed in Windows file names?

The nine reserved characters are `<`, `>`, `:`, `"`, `/`, `\`, `|`, `?` and `*`. Control characters with values 0 through 31 are also not allowed. Spaces, hyphens, underscores and Unicode letters are fine.

### What is the maximum file name length in Windows?

The full path is limited to 260 characters (MAX_PATH) unless long paths are enabled and the app supports them. A single file or folder name is commonly limited to 255 characters. Long paths can be enabled on Windows 10, version 1607, and later through the `LongPathsEnabled` registry value or the "Enable Win32 long paths" Group Policy.

### Does File Explorer sort file10 before file2?

Not by default. File Explorer sorts by numeric value, so `file2` comes first. It sorts `file10` first only when the "Turn off numerical sorting in File Explorer" policy is enabled. Zero-padded names such as `file02` and `file10` sort correctly either way.

### Can I name a file CON or NUL on Windows?

No. `CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9` and `LPT1` to `LPT9` are reserved device names, and adding an extension such as `NUL.txt` does not make them valid.

### Why won't OneDrive sync a file that Windows accepts?

OneDrive and SharePoint block some names Windows allows: `.lock`, `_vti_`, `COM0`, `LPT0`, names starting with `~$`, and names with a leading space. Rename the file, or let the OneDrive sync app replace invalid characters with underscores.
